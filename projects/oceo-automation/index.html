AI-powered engagement automation for a CVP's office

I rebuilt the engagement workflow for Microsoft's Security Marketing CVP from three disconnected manual processes into one AI-assisted pipeline. The same architectural pattern later scaled to a seven-agent system at Amazon.

Built 2025Role Business Manager, CVP executive staffStack Power Automate · AI Builder · SharePointImpact ~80% less processing time

Short version. The Security Marketing CVP's office received a steady flow of engagement requests — speaking invitations, customer meetings, partner events, media inquiries. Managing them took three separate manual workflows. I designed and deployed an AI-assisted pipeline that reads each request, extracts the key details, and stages everything for human review. Nothing goes out without a person reading it first.

The problem

When I joined the Security Marketing CVP's executive staff as Business Manager, engagement management ran on three disconnected workflows:

BeforeWhat it meant
Requests tracked across email, spreadsheets and a shared docNo single source of truth. The same request updated in multiple places, or not at all
Every email opened and read manually to extract detailsHigh time cost per request, prone to missed details
No weekly digest or decision cadenceRequests sat until someone asked about them
Decline replies written from scratch each timeInconsistent tone, more time per decision

What I built

A single pipeline that consolidates intake, triage and response into one system, with AI handling the reading and drafting — and a human always making the call.

Workflow 1: Intake and extraction

When a new engagement request arrives in the shared inbox, a Power Automate flow triggers AI Builder (GPT-4o mini) to read the email and extract structured fields: event name, date, requesting organization, requestor, format, audience size and a two-sentence summary. These land as a new row in a SharePoint List — one row per request, every request in one place.

Workflow 2: Weekly digest and triage

Every Monday, a second flow compiles all open requests into a single digest email for the team. Each entry carries its AI-generated summary, so nobody has to open individual threads to know what's waiting. The team triages from the digest and updates statuses directly in the list.

Workflow 3: Response drafting

When a request is marked "Decline," a third flow drafts a polite, personalized reply using the extracted details and saves it to the team's Drafts folder. A staff member reviews, edits if needed, and sends. For accepted engagements, the same details pour into a briefing template, so the prep document starts mostly filled in.

The one rule

Set before anything was built: the human is always the final sender. AI reads, extracts, summarizes and drafts. A person reviews every extraction, makes every accept/decline decision, and sends every reply. This wasn't a guardrail added later — it was the design constraint from day one.

The tech stack

ToolRole in the system
Power AutomateOrchestration — triggers on new emails, compiles the weekly digest, routes decline drafts
AI Builder (GPT-4o mini)Reads each email, extracts structured fields, generates decline drafts and briefing pre-fills
SharePoint ListsThe tracker itself — one row per request with filtered views for triage, scheduling and production
OutlookShared inbox for intake, Drafts folder for staged replies
WordBriefing template, auto-populated from the list

The entire stack runs on tools most Microsoft 365 organizations already have. No new procurement, no external APIs, no engineering support needed.

What carried forward

This system proved the pattern: AI handles the reading and drafting, a shared list is the single source of truth, and a human always makes the final call. When I moved to Amazon's CEO Communications team, I applied the same architecture at a larger scale — a seven-agent system managing 200+ CEO engagement items across intake, triage, briefing production and knowledge retrieval.

The Microsoft build also led to the engagement tracker template, a generalized version that any office can set up, and to briefing evals, a test suite for the failure mode I worry about most: an AI drafter that invents what it wasn't given.
