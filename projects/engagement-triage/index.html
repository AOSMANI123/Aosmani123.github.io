One tracker instead of three: AI-assisted engagement triage

At Microsoft I rebuilt how a Corporate Vice President's office handled engagement requests. Three manual workflows became one pipeline, and per-engagement update time fell 80%.

Where Microsoft Security MarketingWhen 2025–2026My role Designed and built itStack Power Automate · AI Builder · SharePoint

Short version. Requests for the CVP came in as email threads and were tracked in three separate manual workflows. I built one pipeline on tools the team already used: AI pulls the facts out of each request, a Monday digest surfaces what needs a decision, and declines get drafted for a person to edit and send. Update time per engagement fell 80%. The template is open for anyone to reuse.

The problem

I was on the executive staff for the CVP of a roughly 150-person marketing organization. Engagement requests (speaking invitations, customer meetings, events) arrived as email threads. Keeping track of them took three separate manual workflows, so every update meant re-keying the same facts.

The slow part wasn't storing requests. It was reading them. Someone had to open each thread and pull out the event, the date, who was asking and what they wanted before anyone could make a call.

The constraint I designed around

These requests go to a senior executive. A wrong date or a made-up detail in a brief costs more than the time the automation saves. So the rule was set before anything was built: the human is always the final sender. AI can read, extract, summarize and draft. A person decides and sends.

Options on the table

Option A

Tighten the manual process

One spreadsheet, stricter habits. No new tools, but it keeps the reading bottleneck.

Option B

Adopt a dedicated tool

An event or CRM product. More features, but a new system to procure and learn.

Option C · Chosen

Build on what the team used

Outlook, SharePoint and Power Automate were already in daily use, with AI Builder added for the reading.

What I built

PieceWhat it does
IntakeAI Builder prompts read each new request and fill a SharePoint List: event name, date, requestor, organization, industry, a short summary and a suggested next step.
ViewsOne list, filtered for each reader: Triage, Schedule, a Chief of Staff view, a Production tracker and All items.
Monday digestTwo emails every Monday. One lists open requests that need a decision, each with its summary. The other is the decline queue, so low-fit asks clear in one sitting.
Drafted declinesWhen a request is marked for decline, AI drafts a polite reply into the Drafts folder. Staff edit it and send it from their own mailbox.
Brief assemblyFor accepted engagements, a second flow maps the list fields into the brief template, so the document arrives mostly assembled and ready for review.

The same pattern, applied again

I used the same approach for the CVP's meeting follow-ups around RSA Conference 2026. Raw notes went into a form; AI Builder turned them into draft follow-up emails and OneNote pages in the CVP's usual recap format. A person reviewed and sent each one.

MeasureResult
Time per recapAbout 10 minutes, roughly 70% less
Customer follow-ups delivered in the target window11, in a standard format

What carried forward

At Amazon, the same design rules shaped a larger build: a seven-agent system for the CEO's engagement portfolio. The human is still the final sender, and each agent owns one stage with a clear handoff. It also pushed me to build briefing evals, a small test suite that checks whether an AI drafter invents facts it wasn't given.

Use the template

The template folder has a generic version you can rebuild in any Microsoft 365 tenant: the list schema, the three prompts and a setup order. None of it contains Microsoft's internal data.
