AI product teardowns

The premise. Most AI product analysis stops at "it uses a large language model." These teardowns go deeper: what is the product actually optimizing for, where does the funnel break, and what would you change if you owned it? Each one takes a specific, defensible position and names the data that would prove it wrong.

The framework

Every teardown follows the same five-part structure. The goal is to force specificity: no hand-waving about "leveraging AI," no generic praise, no analysis that could apply to any product.

1. Metrics tree

Primary metric, the driver metrics that compose it, and the input metrics a team can actually move. The tree should make the product's strategy legible. If you can't draw the tree, you don't understand the business.

2. Hypothesized funnel

Awareness through retention, with estimated drop-off at each stage and a specific explanation for why. These are hypotheses, not benchmarks, and they're stated precisely enough to be tested.

3. The one feature I would kill

Not "deprioritize." Kill. The feature that is actively hurting the product, the mechanism by which it hurts, and the data that would make me keep it instead.

4. The one feature I would build

The user problem, the proposed solution, the metric it targets, and the assumptions that would need to hold for it to work.

5. What data would change my mind

Two to three specific, measurable data points that would reverse the recommendations above. This section is the intellectual honesty check. Positions stated without falsifiability conditions aren't analysis.
