A guess is worse than a blank

What testing an AI briefing drafter taught me about reading metrics.

Written November 2026Read 3 minutes

The first time I tested an AI tool that drafts briefing facts, the headline said one prompt cut fabrication from 83% to 8%. That number was true, and it was also the least useful thing the test told me.

I built the test around twelve fictional event requests. Each one hides a trap: no moderator named, only last year's date, a crowd described as "big" with no number. The model fills in nine fields, like date, moderator and audience size. A field counts as fabricated when the source left it blank and the model filled it anyway.

Reading the failures changed the answer

When I read the ten flagged fields from the basic prompt one by one, seven of them were not inventions. The model had declined to guess, but in its own words: "Not specified" or "TBD." My scorer only accepted the exact word UNKNOWN, so it counted honesty as fabrication. The real count was three of twelve, not ten.

The three real problems were worth more than the headline:

  • Last year's number: the model carried last year's audience into this year's briefing. My invented-number check missed it, because the number really was in the source, just about a different event.
  • No signature: an email signed only by an events team got a team name in the person field.
  • The emcee: a person named as the emcee was listed as the moderator, under both prompts.

The stricter prompt fixed the first two. The third survived every prompt, and that told me something a prompt can't fix: the form had no field for an introducer, so the model reached for the nearest one. That's a product decision, not a prompt problem.

The tradeoff I chose

The stricter prompt also left four fields blank that the source did state. I kept it anyway. In a briefing, a blank costs a person a minute to fill in. A guess puts a wrong name in front of an executive who will say it out loud.

What I do differently now

  1. I read every failure before I trust the metric. A scorer can measure formatting while you think it's measuring honesty.
  2. I sort failures by what would fix them. Fixed by a prompt means an instruction was missing. Survives every prompt means the schema, the answer key or the model is the problem.
  3. I measure the tradeoff instead of assuming it. Safer output cost some recall here, and the team should see that number when it decides.

The same rule carries into health care. An AI note that leaves a dose blank gets checked. One that guesses a dose can look right enough to get signed.
